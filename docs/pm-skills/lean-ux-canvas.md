# Lean UX Canvas

**Type:** Component
**Source:** [deanpeters/Product-Manager-Skills](https://github.com/deanpeters/Product-Manager-Skills/blob/main/skills/lean-ux-canvas/SKILL.md)

---

## Purpose

A one-page facilitation tool (Jeff Gothelf's Lean UX Canvas v2) that frames work around business problems rather than predetermined solutions. Serves as an "insurance policy" that exposes gaps in understanding before development begins.

Use when starting initiatives, reframing projects, aligning cross-functional teams, or planning discovery phases. Skip for tactical bug fixes, already-validated problems, or when stakeholders reject evidence-based approaches.

---

## Eight-Box Structure

| Box | Question |
|---|---|
| 1. Business Problem | What changed that created this opportunity? |
| 2. Business Outcomes | What measurable behaviour shifts indicate success? |
| 3. Users | Which personas deserve focus first? |
| 4. User Outcomes & Benefits | What value would users gain? |
| 5. Solutions | What features or initiatives might address the problem? |
| 6. Hypotheses | Testable assumptions combining the above boxes |
| 7. Most Important Learning | The riskiest assumption to validate |
| 8. Least Work Needed | The smallest experiment to test that assumption |

---

## Critical Distinctions

**Box 2 vs Box 4:** Business outcomes are measurable behaviour change (metrics). User outcomes are goals, benefits, and emotional drivers. One is quantitative; the other is empathetic.

**Box 5 (Solutions) is exploration, not commitment.** This prevents premature solution-locking before validation occurs.

---

## Common Failure Modes

- Starting with solutions instead of problems
- Vague business outcomes lacking measurable criteria
- Overly broad user segments
- Confusing behavioural metrics with emotional benefits
- Single-solution thinking in Box 5
- Skipping Box 8 (experiment design)
