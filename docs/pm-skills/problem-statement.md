# Problem Statement

**Type:** Component
**Source:** [deanpeters/Product-Manager-Skills](https://github.com/deanpeters/Product-Manager-Skills/blob/main/skills/problem-statement/SKILL.md)

---

## Purpose

A user-centred framework for articulating problems empathetically before jumping to solutions. Structures problems around who is blocked, what they're trying to achieve, underlying barriers, root causes, and emotional impact.

Use when kicking off discovery, aligning stakeholders before designing solutions, or converting feature requests into user-centred problems.

---

## Five-Part Framework

```
PROBLEM STATEMENT

I am: [specific persona — 3–4 defining characteristics]
Trying to: [desired outcome — measurable, not a task]
But: [real barriers preventing success]
Because: [root cause — not symptoms]
Which makes me feel: [authentic emotion from research]

Context/Constraints: [relevant situational factors]

One-sentence problem statement: [synthesise above into one sentence]
```

---

## Quality Checkpoints

- Can you vividly picture the persona?
- Is the desired outcome measurable?
- Are barriers substantive, not trivial?
- Is the root cause a root cause, or a symptom? (Keep asking "why")
- Was the emotion grounded in actual user research?
- Does the final statement fit one sentence?

---

## Anti-Patterns

| Anti-Pattern | Example | Fix |
|---|---|---|
| Solution smuggling | "Problem is we lack AI analytics" | Focus on desired outcomes, not features |
| Business metrics as user problems | "Churn rate is rising" | Reframe from user perspective |
| Generic personas | "Busy professionals want productivity" | Get specific |
| Symptom over root cause | "Because the UI confuses users" | Keep asking "why" |
| Fabricated emotions | "Empowered and delighted" | Ground in actual research |
