# Prioritization Advisor

**Type:** Interactive
**Source:** [deanpeters/Product-Manager-Skills](https://github.com/deanpeters/Product-Manager-Skills/blob/main/skills/prioritization-advisor/SKILL.md)

---

## Purpose

Helps you select the right prioritization framework for your context. The mistake isn't using the wrong framework — it's applying any framework without matching it to your product stage, team, and data availability.

> "Frameworks aren't 'better' or 'worse' — they fit different contexts."

---

## Four Diagnostic Questions

The skill asks these to narrow to the right framework:

1. **Product stage** — Pre-PMF / early scaling / mature / multi-product?
2. **Team context** — Solo / small aligned / misaligned stakeholders / large org?
3. **Decision-making need** — Too many ideas / stakeholder disagreement / lack of data / strategic tradeoffs?
4. **Data availability** — Minimal / some / rich?

---

## Framework Recommendations

| Context | Framework | Why |
|---|---|---|
| Mature product, rich data, aligned team | RICE | Reach × Impact × Confidence ÷ Effort — rigorous scoring |
| Speed matters, limited data | ICE | Impact × Confidence × Ease — lightweight gut-check |
| Visual thinkers, strategic tradeoffs | Value/Effort Matrix | Quick wins vs. strategic bets |
| Customer satisfaction focus | Kano Model | Categorises features as must-have / performance / delighter |
| Delay has cost | Cost of Delay | Prioritises by revenue or value lost per unit of time |
| Complex backlog, need sequencing | Story Mapping | User journey-based ordering |
| Stakeholder disagreement | MoSCoW | Must/Should/Could/Won't — forces explicit trade-offs |

---

## For FeedMe

FeedMe is a mature personal product (most core features built) with a single decision-maker (you) and a clear backlog in `TODO.md` and `docs/PRD.md`. Recommended starting point:

**ICE** for quick wins (copy button, native share, URL scrape improvements)
**Value/Effort Matrix** for medium-effort features (dietary profile, streaming, supermarket links)
**Problem Framing Canvas first** for big features (browser extension, multi-user)

---

## Common Pitfalls

- **Inflating confidence scores** — "I'm sure users want this" isn't a data point
- **Solo scoring without a gut-check** — even as a solo PM, step back and challenge your scores
- **Switching frameworks constantly** — pick one per planning cycle and commit to it
- **Applying RICE to unvalidated ideas** — RICE needs data; use ICE or Cost of Delay earlier
