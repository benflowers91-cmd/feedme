# PM Skill Creator

**Type:** Interactive
**Source:** [deanpeters/Product-Manager-Skills](https://github.com/deanpeters/Product-Manager-Skills/blob/main/skills/pm-skill-creator/SKILL.md)

---

## Purpose

Guides you from a raw idea or content to a complete, repository-compliant SKILL.md draft through adaptive questioning. Use this to create new skills for this library.

---

## Five-Question Process

1. **Raw Material** — Is the input a framework, template, process, or advisory topic?
2. **Type Decision** — Component / Interactive / Workflow?
3. **Scope & Naming** — Kebab-case name (≤64 chars) and 200-char trigger-focused description
4. **Key Content** — Core elements adapted to skill type (template + criteria, conversation flow, or phase map)
5. **Pitfalls & Edge Cases** — 2–3 failure modes with consequences and fixes

---

## Non-Negotiable Skill Anatomy

Every skill requires these sections in order:
1. Purpose (outcome-focused)
2. Key Concepts (frameworks, definitions)
3. Application (step-by-step instructions)
4. Examples (at least one concrete case)
5. Common Pitfalls (named failure modes with fixes)
6. References (related skills, external sources)

---

## Critical Rules

**Description Trigger Rule:** Must answer "Use when..." to enable accurate skill matching. Generic descriptions cause the skill to remain undiscovered.

**Scope Discipline:** Single skills handle one job. Multiple branches, phases, or more than 6 application steps typically indicates the need for separate skills.

**Validation Non-Negotiable:** Metadata validation, trigger verification, and smoke testing before deployment.

---

## Common Failure Modes

- Type confusion (treating templates as workflows)
- Non-triggering descriptions lacking context cues
- Scope creep attempting to cover entire domains
- Skipping validation
