# User Story Mapping

**Type:** Component
**Source:** [deanpeters/Product-Manager-Skills](https://github.com/deanpeters/Product-Manager-Skills/blob/main/skills/user-story-mapping/SKILL.md)

---

## Purpose

Strategic visualisation tool that organises work around user journeys rather than feature lists or project timelines. Creates a hierarchical narrative showing how users accomplish goals.

Use when launching new products or major features, aligning teams on user workflows, building backlog priorities around actual user needs, or defining MVP scope versus future iterations.

---

## Two-Dimensional Structure

**Horizontal (left-to-right):** Activities → Steps → Tasks (user's timeline)

**Vertical (top-to-bottom):** Priority levels — MVP tasks at the top, future enhancements below

---

## Seven Application Steps

1. **Define Context** — Identify specific segment and persona
2. **Establish Narrative** — Frame as a JTBD outcome statement
3. **Map Activities** — 3–5 high-level user behaviours (the backbone)
4. **Detail Steps** — 3–5 specific actions under each activity
5. **List Tasks** — Granular work items under each step
6. **Prioritise Vertically** — Distinguish MVP from future releases
7. **Identify Gaps** — Surface missing steps or opportunities

---

## Common Mistakes

- Mapping features instead of user behaviours
- Creating 10+ activities — consolidate to 3–5
- Writing vague tasks — be specific and observable
- Neglecting vertical prioritisation
- Developing the map in isolation rather than collaboratively
