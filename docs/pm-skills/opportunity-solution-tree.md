# Opportunity Solution Tree

**Type:** Interactive
**Source:** [deanpeters/Product-Manager-Skills](https://github.com/deanpeters/Product-Manager-Skills/blob/main/skills/opportunity-solution-tree/SKILL.md)

---

## Purpose

Transforms vague stakeholder requests into validated opportunities with testable hypotheses. Avoids premature solution convergence by structuring discovery hierarchically.

**Use for:** vague feature requests needing problem framing, new product area discovery, clarifying ambiguous OKRs, prioritising which problems to solve.

**Skip for:** already-validated problems (move to solution testing), tactical bug fixes, situations where stakeholders demand specific solutions.

---

## Four-Level Hierarchy

1. **Desired Outcome** — measurable business goal
2. **Opportunities** — customer problems or needs (not solutions)
3. **Solutions** — approaches to address each opportunity
4. **Experiments** — validation tests

Structure diverges from one outcome into multiple opportunities and solutions, before converging on a proof-of-concept to test.

---

## Two-Phase Process

**Phase 1: Generate OST**
- Extract desired outcome from stakeholder context
- Identify 3 opportunities (problems, not solutions)
- Map 3 potential solutions per opportunity
- Ensure all elements are problem-focused and testable

**Phase 2: Select POC**
- Score each solution on feasibility, impact, and market fit (1–5 scale)
- Recommend best starting point with clear hypothesis
- Define specific experiment type and success criteria

---

## Critical Anti-Patterns

1. **Opportunities disguised as solutions** — "We need a mobile app" → reframe as "Mobile users can't access our product"
2. **Skipping divergence** — jumping to one solution without exploring alternatives
3. **Vague outcomes** — "Improve UX" instead of "Reduce onboarding drop-off from 60% to 40%"
4. **No experiments** — picking solutions without validation plans
5. **Analysis paralysis** — exploring endlessly instead of limiting to 3 opportunities × 3 solutions

---

## Reminder

An OST is a discovery tool — not a roadmap or feature list. Requires continuous iteration based on experimental learning.
