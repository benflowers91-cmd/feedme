# Storyboard

**Type:** Component
**Source:** [deanpeters/Product-Manager-Skills](https://github.com/deanpeters/Product-Manager-Skills/blob/main/skills/storyboard/SKILL.md)

---

## Purpose

Creates a 6-frame emotional narrative showing a user's journey from problem to solution. Use for stakeholder alignment, concept validation, and vision communication — not UI mockups or technical documentation.

Stories build empathy more effectively than specifications. Visual narratives make abstract concepts tangible and memorable, enabling feedback on emotional resonance *before* development begins.

---

## 6-Frame Narrative Arc

| Frame | Content |
|---|---|
| 1. Main Character | Persona introduction with context |
| 2. Problem Emerges | Challenge presentation |
| 3. "Oh Crap" Moment | Problem escalation |
| 4. Solution Appears | Product introduction |
| 5. "Aha" Moment | Breakthrough experience |
| 6. Life After | Improved outcome state |

---

## Application Process

1. Gather context — confirm persona, problem, solution, and desired outcomes
2. Answer 7 questions about character, challenge, escalation, solution discovery, breakthrough, and post-solution life
3. Draft frame-by-frame narrative focusing on emotional beats, not feature lists
4. Visualise — sketches, AI-generated images, or diagrams
5. Test — is it relatable? Emotionally impactful? Authentic? Aspirational?

---

## Common Pitfalls

- Generic personas — "a busy professional" lacks specificity for identification
- Weak problems — if the problem doesn't feel urgent, the solution won't feel valuable
- Forced solutions — inauthentic product placement breaks the narrative
- Feature-focused frames — the "aha" moment should be emotional, not a feature demo
- Vague outcomes — "life after" must be aspirational and specific

---

## When NOT to Use

Technical implementation planning, trivial problems, or as a replacement for customer research.
